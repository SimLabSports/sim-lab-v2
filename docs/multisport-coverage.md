# Sim Lab multi-sport coverage and implementation

Audit: October 20, 2026. Exact machine-readable receipts are in `data/multisport-source-audit.json` and `data/multisport-history-audit.json`. Counts are snapshots, not promises about the next provider response. `/api/statistics/coverage` combines those receipts with the current catalog, credential presence, latest saved GCM evaluations and reviewed model inventory. A worker's empty cache is explicitly NOT_FETCHED, not a disconnected league.

## Shared architecture

`sport-profiles.ts` supplies separate performance requirements and competition mappings for football, basketball, baseball, hockey, soccer, tennis, combat and golf. `event-identity.ts` preserves the Odds event ID, sport, start and normalized participants plus exact provider bindings. Team matching is directional; individual matching is an unordered pair. No fuzzy name matching or automatic cross-competition substitution is used. Match timing is within 15 minutes; ambiguous or postponed matches fail closed.

`getStatistics` runs independent available providers together, isolates failures, merges only matched pregame packets and retains their actual observation times and missing coverage. The shared AI interpreter receives only source evidence and the sport's required features, never sportsbook prices or expert votes. Soccer explicitly evaluates both teams **and Draw**. Tennis uses singles draw results; UFC uses actual fighter records when the exact bout matches. A record or tournament win rate is never a calibrated win probability.

The shared reviewed-model and rule engines remain responsible for probability, price value, category and approval. The MLB model is never used for another sport. A sport's qualitative research working does not mean official approval is ready.

## Endpoints and credentials

No new credential is required for the public-source adapters in this pass. ESPN sources are publicly reachable research feeds, not a claimed licensed commercial SLA. Source availability and commercial redistribution rights are separate questions.

- Existing market connection: `ODDS_API_KEY`; Fanatics remains the only selected sportsbook. Tennis and soccer use their active league catalogs; MMA and Boxing now request their actual league, rather than only inspecting an empty all-sports cache. Golf requests an active outright competition and the existing Futures market.
- Optional multi-sport supplement: existing `BALLDONTLIE_API_KEY`. Basic entitlement does not unlock stats, injuries, lineups or advanced features for every sport. Actual endpoint success governs coverage; one denied endpoint does not block public sources or other sports.
- AI research: existing `OPENAI_API_KEY`, `OPENAI_MODEL`; persisted audit: existing `DATABASE_URL`. Explicit scans retain the existing shared budgets. Passive polling never initiates paid research.
- Expert import: existing `SIMLAB_ADMIN_TOKEN`, administrator session and same-origin request. `/api/admin/expert-picks` imports one actual pick; `/api/admin/expert-picks/batch` accepts 1–25 reviewed picks across sports with per-item results. Batch imports are explicitly non-atomic; rejected rows add no vote. Each pick still needs analyst/origin/organization, HTTPS source, publication/expiry, display rights and exact offered selection/line.
- Public team endpoints: `{sport}/{league}/scoreboard`, `teams/{id}/schedule`, `teams/{id}/statistics`, `summary?event={id}` under `https://site.api.espn.com/apis/site/v2/sports/`. Soccer uses native FULL_TIME results. Team-stat sample mismatches are withheld.
- Individual endpoints: `tennis/atp/scoreboard`, `tennis/wta/scoreboard`, `mma/ufc/scoreboard`, `golf/pga/scoreboard`. Singles/individual, combat and field structures are handled separately. No surface or medical status is inferred from a venue or an empty injury list.

## Historical work

`scripts/collect-multisport-results.mjs` collects real source-attributed completed team results for verified IDs and seasons. In this pass it collected 51 WNBA, 8 NHL, 6 NCAA Football and 7 EPL results from bounded team samples. It does not call them league-wide datasets or automatically train/promote a model. NHL requests returning the wrong season were rejected, rather than silently relabeled.

`history-contract.ts` requires sport, exact outcome target, settlement definition, source references, pre-decision feature observation times and a later settled result. Soccer must include Draw; field markets cannot be approximated by two complements. The collected results currently lack the required historical pregame feature snapshots and completion timing, so they are explicitly marked ineligible for point-in-time training. The existing MLB chronology/calibration audit remains separate.

## Multi-sport provider investigation — no purchases made or recommended

| Provider | Finding | Why it does not automatically supply three checks |
|---|---|---|
| [BALLDONTLIE](https://docs.balldontlie.io/) | One API ecosystem covers multiple US sports, soccer, tennis and others; endpoint entitlement differs by sport/plan | Statistics access is not three independent analyst/model origins or a validated custom GCM |
| [SportsDataIO](https://sportsdata.io/developers) | Deep Leagues APIs cover multiple sports. Global Sports API is broad schedules/scores, not all advanced features. Trial data is scrambled; Discovery Lab is next-day delayed | A broad catalog is not complete live injury/lineup or independently sourced consensus coverage |
| [API-SPORTS](https://api-sports.io/) | Multiple sport products under one account/key; competition and endpoint depth vary | A single key does not guarantee every sport's required features, historical injuries or source independence |
| [Sportradar / Tallysight Insights](https://developer.sportradar.com/insights/reference/insights-overview) | Documented expert-pick/consensus product and a multi-sport ecosystem | Need actual licensed payloads exposing identities, exact selections, timestamps and independent origins; an aggregate percentage alone cannot satisfy the three-source rule |
| [Sportmonks Predictions](https://docs.sportmonks.com/v3/endpoints-and-entities/endpoints/predictions) | Soccer prediction model with documented market probabilities | One model origin is one source, not three. Soccer coverage is not a solution for every other sport |

No external model, sportsbook consensus price, public popularity count or GCM output has been manufactured into expert votes. No additional subscription, API key or automated test suite was purchased or created.
